# Каталог товаров с синхронизацией фильтров и URL

Полнофункциональное Single Page Application (SPA) каталога товаров на базе **DummyJSON API**, разработанное в соответствии с высокими стандартами коммерческой фронтенд-разработки.

---

## 🚀 Технологический стек

* **Frontend:** React 19, TypeScript (строгий режим `strict: true`, `verbatimModuleSyntax`, `erasableSyntaxOnly`)
* **Сборка и dev-сервер:** Vite 8
* **Управление серверным состоянием и API:** Redux Toolkit 2.x, RTK Query
* **Управление клиентским состоянием:** Redux Toolkit (`favoritesSlice` + `localStorage` persistence)
* **Маршрутизация:** React Router v7 (`createBrowserRouter`)
* **Стилизация:** SCSS Modules (`.module.scss`) с системой дизайн-токенов и адаптивными миксинами
* **Линтинг и качество кода:** Oxlint, TypeScript Compiler (`tsc`)

---

## 📋 Реализованный функционал

### 1. Каталог товаров (`/`)
* Карточки товаров: изображение (с fallback при ошибке загрузки), название, цена, размер скидки, пересчет старой цены, рейтинг (со звездой), статус наличия (`In Stock` / `Low Stock` / `Out of Stock`) и кнопка добавления в избранное.
* Защита от отсутствующих полей (graceful degradation) — интерфейс не ломается при неполных ответах API.
* Бесконечная пагинация (Infinite Scroll) при прокрутке вниз с использованием `IntersectionObserver`.

### 2. Поиск и фильтрация
* **Поиск (`q`) с двойным триггером:**
  * Запрос отправляется **мгновенно** при длине строки, кратной 4 символам (4, 8, 12...);
  * Либо **через 400 мс** после паузы при вводе остальных символов (debounce);
  * Кнопка мгновенной очистки поля поиска.
* **Категории:**
  * Получение списка категорий с сервера (`/products/categories`);
  * Выбор и сброс категории;
  * Загрузка товаров категории через соответствующий endpoint DummyJSON (`/products/category/:category`).
* **Сортировка:**
  * Поля: цена (`price`), название (`title`), рейтинг (`rating`), размер скидки (`discountPercentage`);
  * Направления: по возрастанию (`asc`) и убыванию (`desc`).
* **Фильтрация по датам:**
  * Параметры `modifiedAfter` и `modifiedBefore` (серверная фильтрация DummyJSON по полю `meta.updatedAt`);
  * Выбор дат и кнопка сброса.

### 3. Двусторонняя синхронизация фильтров с URL
* URL (`window.location.search`) — **единственный источник правды** (Single Source of Truth) для фильтров.
* Все фильтры автоматически восстанавливаются при открытии прямой ссылки или обновлении страницы (F5).
* Поддержка навигации браузера: кнопки «Назад» и «Вперёд» корректно переключают состояния каталога.
* Поиск обновляет URL через `replace: true`, чтобы не засорять историю каждым введенным символом; выбор категории/сортировки/дат создает новый шаг в истории (`pushState`).
* Пустые и дефолтные параметры удаляются из URL, обеспечивая чистые и понятные ссылки (`/?q=phone`).
* Некорректные параметры безопасно валидируются и нормализуются.

### 4. Страница товара (`/products/:id`)
* Получение ID из параметров маршрута и загрузка отдельным запросом `GET /products/{id}` через RTK Query.
* Интерактивная галерея изображений с переключением миниатюр.
* Детальная информация: бренд, категория, рейтинг, количество отзывов, статус наличия, цена, скидка, описание, таблица характеристик (SKU, габариты, вес, условия гарантии, доставки и возврата) и список проверенных отзывов.
* Добавление/удаление из избранного.
* Кнопка «Назад в каталог» гарантированно сохраняет все фильтры, использованные при переходе из каталога (через `location.state.fromSearch`).
* Обработка состояний загрузки (скелетоны), ошибок и отсутствия товара (404).

### 5. Избранное (Favorites)
* Глобальное состояние на Redux Toolkit (`favoritesSlice`).
* В Redux хранятся исключительно идентификаторы товаров `ids: number[]` (серверные данные не дублируются).
* Идемпотентность: защита от дубликатов при добавлении.
* Автоматическая синхронизация с `localStorage` (`product_catalog_favorites`).
* Счетчик избранных товаров в шапке сайта, обновляющийся в реальном времени.
* Отдельная страница избранного (`/favorites`) с карточками товаров, возможностью удаления, кнопкой очистки списка и информативным пустым состоянием.

## 🏛️ Архитектура приложения

Приложение спроектировано по принципам модульности и разделения ответственности (Separation of Concerns):

```
src/
├── api/                           # RTK Query API слой
│   ├── productsApi.ts             # Определение createApi, всех эндпоинтов и хуков
│   └── products.types.ts          # Реэкспорт типов API
├── app/                           # Конфигурация Redux
│   ├── store.ts                   # Redux store с middleware и подпиской на localStorage
│   └── hooks.ts                   # Строго типизированные useAppDispatch, useAppSelector
├── features/                      # Бизнес-модули
│   ├── favorites/                 # Избранное (слайс, экшены, селекторы, storage)
│   └── filters/                   # Синхронизация URL и хук useCatalogFilters
├── components/                    # UI компоненты
│   ├── common/                    # Базовые атомы (Button, Input, Select, Badge, Skeleton, StatePlaceholder)
│   ├── Layout/                    # Каркас приложения и Header со счетчиком
│   ├── Product/                   # Доменные карточки, сетка и галерея
│   └── Catalog/                   # Поисковая строка и панель фильтров
├── pages/                         # Представления маршрутов
│   ├── CatalogPage/               # Главная страница каталога
│   ├── ProductDetailsPage/        # Страница товара /products/:id
│   ├── FavoritesPage/             # Страница избранного /favorites
│   └── NotFoundPage/              # Страница 404
├── router/                        # Маршрутизация React Router v7
│   └── AppRouter.tsx              # Конфигурация маршрутов createBrowserRouter
├── styles/                        # SCSS Modules и дизайн-система
│   ├── _variables.scss            # Дизайн-токены (цвета, шрифты, отступы, тени)
│   ├── _mixins.scss               # Миксины для медиазапросов и эффектов
│   ├── _reset.scss                # Сброс базовых стилей
│   └── index.scss                 # Точка входа глобальных стилей
└── types/                         # TypeScript интерфейсы
    ├── product.ts                 # Сущность Product, Review, Dimensions, Meta
    └── api.ts                     # QueryParams, Sort, Mutation payloads
```

### Ключевые архитектурные решения

1. **Разделение серверного и клиентского состояния:**
   * Серверные данные кешируются RTK Query.
   * Клиентское глобальное состояние содержит только ID избранного (`favoritesSlice`).
   * Фильтры живут в URL (`searchParams`).

2. **Бесконечная пагинация в RTK Query:**
   * В эндпоинте `getProducts` использован `serializeQueryArgs` (исключающий параметр `skip` из ключа кеша) в сочетании с `merge` (объединяющим порции данных и дедуплицирующим их по `id`).
   * Это позволяет сохранять накопленный список товаров в кеше RTK Query без создания избыточных ручных срезов Redux.

## 🛠️ Установка и запуск

### 1. Установка зависимостей
```bash
npm install
```

### 2. Запуск в режиме разработки
```bash
npm run dev
```
Приложение откроется по адресу `http://localhost:5173/`.

### 3. Сборка для production
```bash
npm run build
```
Выполняет проверку типов (`tsc -b`) и собирает оптимизированный бандл через `vite build`.

### 4. Проверка линтером
```bash
npm run lint
```
