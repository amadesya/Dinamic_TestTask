# Product Catalog

Современный каталог товаров с поиском, фильтрацией, пагинацией и избранным, разработанный на базе публичного API **DummyJSON**.

Проект выполнен в рамках тестового задания на позицию Frontend-разработчика с упором на надежную архитектуру, строгую типизацию, производительность и доступность интерфейса.

---

## 📋 Основные возможности

* **Каталог товаров:** адаптивная сетка карточек с отображением цен, скидок, рейтингов, остатков на складе и статуса добавления в избранное.
* **Поиск товаров с двойным триггером:**
  * Задержка (debounce) 400 мс при обычном наборе текста.
  * Мгновенная отправка запроса при длине строки, кратной 4 символам (`length % 4 === 0`), без ожидания таймера.
  * Мгновенный сброс результатов при очистке поисковой строки.
* **Фильтрация по категориям:** загрузка актуального списка категорий из API и фильтрация каталога через dedicated endpoint DummyJSON.
* **Фильтрация по датам обновления:** выбор диапазона дат («От» и «До») с фильтрацией по полю `meta.updatedAt` товаров.
* **Сортировка товаров:** сортировка по цене, размеру скидки, рейтингу и названию (в направлениях `asc` и `desc`).
* **Бесконечная прокрутка (Infinite Scroll):** автоматическая дозагрузка товаров порциями по 12 штук через `IntersectionObserver` с дедупликацией элементов.
* **Синхронизация с URL:** браузерная адресная строка является единственным источником правды (SSOT) для всех параметров поиска, фильтрации и сортировки. Поддерживаются закладки, шеринг ссылок, обновление страницы (F5) и навигация кнопками «Назад / Вперёд».
* **Страница детальной информации (`/products/:id`):**
  * Интерактивная фотогалерея с переключением миниатюр.
  * Полный перечень характеристик (SKU, габариты, вес, условия гарантии, доставки и возврата).
  * Блок проверенных отзывов покупателей.
  * Кнопка «Назад в каталог» с гарантированным сохранением всех ранее примененных фильтров.
* **Избранное с сохранением в `localStorage`:** добавление и удаление товаров из списка избранного с персистентным хранением в браузере.
* **Состояния загрузки, ошибок и пустого результата:**
  * Скелетон-загрузчики без сдвигов верстки (Cumulative Layout Shift = 0).
  * Информативные экраны пустых результатов поиска с возможностью быстрого сброса фильтров.
  * Обработка сетевых ошибок с кнопкой повтора запроса.
* **Доступность (A11y):**
  * Поддержка навигации только с клавиатуры с видимыми состояниями `:focus-visible`.
  * Ссылка «Перейти к основному контенту» (Skip to content).
  * Связка `<label>` и элементов форм через `React.useId()`.
  * Поддержка системного режима уменьшения движения (`prefers-reduced-motion: reduce`).

## 🚀 Установка и запуск

### Требования к окружению
* **Node.js:** версия `18.x`, `20.x` или новее
* **npm:** версия `9.x` или новее

### Шаги запуска

1. **Клонировать репозиторий:**
   ```bash
   git clone https://github.com/amadesya/Dinamic_TestTask.git
   cd Dinamic_TestTask/product-catalog
   ```

2. **Установить зависимости:**
   ```bash
   npm install
   ```

3. **Запустить dev-сервер:**
   ```bash
   npm run dev
   ```
   Приложение будет доступно по адресу `http://localhost:5173/`.

### Доступные npm-скрипты

В директории `product-catalog` доступны следующие команды:

| Команда | Назначение |
| :--- | :--- |
| `npm run dev` | Запуск локального сервера разработки с Hot Module Replacement (HMR) |
| `npm run build` | Полная проверка типов TypeScript (`tsc -b`) и production-сборка через Vite |
| `npm run lint` | Быстрая статическая проверка качества кода через Oxlint |
| `npm run preview` | Локальный запуск production-сборки из папки `dist/` для проверки |

## 🏛 Архитектурные решения

1. **Разделение состояния (Server State vs Client State):**
   * Данные о товарах и категориях управляются исключительно через **RTK Query**. Они не дублируются в клиентских слайсах Redux, что устраняет проблемы рассинхронизации данных и устаревшего кэша.
   * Клиентский слайс **`favoritesSlice`** хранит исключительно числовые идентификаторы `ids: number[]`. При открытии страницы избранного данные о конкретных товарах запрашиваются из кэша RTK Query по ID.
2. **URL как Single Source of Truth (SSOT):**
   * Кастомный хук `useCatalogFilters` считывает параметры напрямую из `useSearchParams`.
   * Компоненты каталога не хранят собственное локальное состояние фильтров, что гарантирует полную предсказуемость: ссылка вида `/?category=smartphones&sortBy=price&order=asc&modifiedAfter=2026-01-01` всегда откроет идентичный срез данных у любого пользователя.
3. **Бесконечный скролл в RTK Query:**
   * С помощью настройки `serializeQueryArgs` из ключа кэша исключается параметр смещения `skip`. В результате все последующие страницы пагинации для одних и тех же фильтров попадают в общий кэш-слот.
   * Функция `merge` плавно дополняет массив товаров новыми элементами, автоматически устраняя возможные дубликаты по `id` через `Set`.
4. **Компонентная изоляция:**
   * Каждый компонент инкапсулирован вместе со своим SCSS-модулем.
   * Отсутствуют неявные глобальные селекторы. Контроль компоновки выполняется через строгую систему дизайн-токенов (`_variables.scss`).

## 🌐 Взаимодействие с API (DummyJSON)

Приложение взаимодействует с публичным REST API [DummyJSON Products](https://dummyjson.com/docs/products).

В сервисе `productsApi.ts` реализованы все 10 эндпоинтов спецификации:
* `GET /products` — получение списка товаров с поддержкой пагинации, сортировки и фильтрации по датам (`modifiedAfter`, `modifiedBefore`).
* `GET /products/:id` — детальная информация о товаре.
* `GET /products/search` — полнотекстовый поиск товаров.
* `GET /products/categories` — список категорий с названиями и URL.
* `GET /products/category-list` — список названий категорий.
* `GET /products/category/:category` — получение товаров выбранной категории.
* `POST /products/add` — добавление нового товара.
* `PUT /products/:id` — полное обновление товара.
* `PATCH /products/:id` — частичное обновление товара.
* `DELETE /products/:id` — удаление товара.

> **Примечание:** В соответствии с архитектурой публичного сервиса DummyJSON операции добавления, обновления и удаления (`POST`, `PUT`, `PATCH`, `DELETE`) имитируют успешное выполнение (mock mutations) и возвращают корректный ответ с присвоенным ID, но не сохраняют изменения в реальной базе данных на сервере.
